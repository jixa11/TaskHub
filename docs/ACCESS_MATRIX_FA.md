| نقش | محدوده گزارش درآمد | سهم مالی قراردادها | خروجی PDF/Excel | تنظیم وزن نوع تسک × نوع قرارداد | عملیات مالی |

## قواعد مالی و تیمی

- گزارش شهر و نوع قرارداد داخل همان صفحه گزارش درآمد موجود است و دسترسی جدیدی خارج از `READ_FINANCE_ROLES` ایجاد نمی‌کند.
- `admin`، `finance` و `reporter` نقش‌های مالی سراسری هستند.
- `manager` و `planner` حتی با ارسال دستی شناسه تیم دیگر به API نمی‌توانند خارج از عضویت فعال خود گزارش بگیرند. اگر هیچ عضویت فعال نداشته باشند، خروجی مالی خالی است و Scope به حالت سراسری سقوط نمی‌کند.
- خروجی PDF و Excel از همان تابع داده و همان Scope صفحه ساخته می‌شود؛ Export راه دورزدن سطح دسترسی نیست.
- فقط مدیر سیستم می‌تواند وزن ارتباط نوع تسک و نوع قرارداد را تغییر دهد.
- وزن‌ها مبلغ نیستند و فقط برای ایجاد امتیاز نسبی تسک استفاده می‌شوند.
- سهم مالی فرد و تیم فقط تحلیلی است و حق پرداخت، حقوق، پاداش یا بدهی ایجاد نمی‌کند.
- تسک بدون قرارداد وارد گزارش مالی نمی‌شود و در شاخص کیفیت داده اعلام می‌شود.
- تسک دارای چند مسئول بدون زمان واقعی، سهم مساوی ساختگی تولید نمی‌کند.
- قرارداد انتخاب‌شده روی تسک باید متعلق به همان پروژه باشد؛ فهرست UI به همان پروژه محدود و کنترل نهایی نیز در API ذخیره تسک انجام می‌شود.
- درآمد مبنا فقط مبلغ تأییدشده کارفرما بدون مالیات است.

## پیامرسان

- متن خوانا و کلید خصوصی API مدیریتی ندارند.
- مدیر عادی سامانه، دسترسی مستقیم خواندن دیتابیس و Backup به‌تنهایی برای رمزگشایی پیام خصوصی کافی نیستند.
- پاک‌سازی Cache نسخه ۸.۰.۲ کلید خصوصی IndexedDB را حذف نمی‌کند.
- کنترل کامل فایل‌های اجرایی یا JavaScript سرور خارج از تضمین یک وب‌اپ است.
