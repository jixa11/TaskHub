# راهنمای TaskHub 8.0.2

نسخه ۸.۰.۲ یک Patch افزایشی روی ۸.۰.۱ است. ساختار تیمی و پیامرسان حفظ شده و این موارد اضافه یا اصلاح شده‌اند:

- رفع خودکار Cache و Service Worker نسخه‌های قبلی، بدون پاک‌کردن کلیدهای خصوصی پیامرسان.
- تکمیل همان **گزارش درآمد موجود** با دو نمای جدید «شهر» و «نوع قرارداد»؛ صفحه تکراری ساخته نشده است.
- جایگزینی انواع قرارداد قبلی با `نوع تعیین نشده`، `فروش`، `توسعه` و `پشتیبانی`.
- انتقال یک‌باره تمام قراردادهای موجود به `نوع تعیین نشده`؛ انتخاب نوع جدید اجباری نیست.
- گزارش تحلیلی سهم مالی تیم و فرد بر اساس تسک‌های تکمیل‌شده هر قرارداد.
- خروجی PDF و Excel برای گزارش‌های درآمد، کارکرد، تیمی و سهم مالی.
- اجرای اینترنتی پیشنهادی با IIS/ARR و Waitress؛ پورت داخلی برنامه مستقیم روی اینترنت منتشر نمی‌شود.

تابع `connection_string()` تغییر نکرده است.

## ارتقای امن

1. نسخه قبلی را از Tray و Task Manager کامل ببندید.
2. از دیتابیس و پوشه `taskhub_data` بکاپ کامل بگیرید.
3. نسخه ۸.۰.۲ را در پوشه جدا Extract کنید.
4. فایل `taskhub_config.json` را کنار EXE جدید قرار دهید.
5. `build.bat` را اجرا کنید.
6. اولین اجرا را روی کپی دیتابیس انجام دهید و گزارش‌ها و نقش‌ها را کنترل کنید.
7. فایل `sql\validate_v802.sql` را روی دیتابیس آزمایشی اجرا و ردیف‌های مغایرت را بررسی کنید.
8. پس از تأیید، نسخه عملیاتی را جایگزین کنید.

خروجی‌های ساخت:

- `dist\TaskHub_v8_0_2.exe` برای اجرای دسکتاپ/شبکه داخلی.
- `dist\TaskHubServer_v8_0_2.exe` برای اجرای بدون UI پشت IIS.
- `dist\TaskHubMigration_v8.exe` فقط برای Migration فایل‌های Legacy.
- `dist\TaskHubBackup_v8.exe`
- `dist\TaskHubRestore_v8.exe`

`TaskHubMigration_v8.exe --apply` برای اجرای عادی لازم نیست. قبل از Apply باید خروجی Dry Run و رکوردهای orphan/ambiguous بررسی شوند.

## گزارش درآمد؛ بدون ایجاد صفحه تکراری

صفحه قبلی «درآمد پروژه‌ها» به «گزارش درآمد» توسعه یافته و سه نمای تجمیعی دارد:

- نوع پروژه
- شهر
- نوع قرارداد

فیلترهای شهر، نوع قرارداد، نوع پروژه، پروژه، سال/ماه و بازه تاریخ روی همان گزارش اعمال می‌شوند. جزئیات قراردادها نیز همچنان در همان صفحه در دسترس است. خروجی PDF و Excel مطابق نمای انتخاب‌شده تولید می‌شود.

## انواع قرارداد

انواع فعال نسخه ۸.۰.۲:

| شناسه | عنوان |
|---|---|
| 0 | نوع تعیین نشده |
| 1 | فروش |
| 2 | توسعه |
| 3 | پشتیبانی |

در اولین اجرای موفق نسخه، تمام قراردادهای موجود دقیقاً یک‌بار به `نوع تعیین نشده` منتقل می‌شوند. این مقدار معتبر و فعال است و کاربر مجبور نیست بعداً نوع دیگری انتخاب کند. قراردادهای جدید یا ویرایش‌شده می‌توانند روی هر یک از چهار نوع باقی بمانند.

## گزارش سهم مالی تحلیلی قراردادها

این گزارش یک تب داخل **گزارش‌های تیمی موجود** است و صفحه مستقل تکراری ایجاد نمی‌کند.

شرط ورود یک تسک به محاسبه:

- وضعیت تسک `done` باشد.
- قرارداد مرتبط روی تسک انتخاب شده باشد.
- قرارداد متعلق به همان پروژه تسک باشد.

امتیاز غیرریالی هر تسک:

```text
امتیاز تسک = وزن پیشرفت تسک × وزن نوع تسک در نوع قرارداد
```

وزن ارتباط «نوع تسک × نوع قرارداد» توسط مدیر سیستم تنظیم می‌شود و مقدار پیش‌فرض همه ترکیب‌ها `1` است.

### سهم تیم

مجموع امتیاز تسک‌های تکمیل‌شده هر تیم روی قرارداد بر مجموع امتیاز تمام تسک‌های تکمیل‌شده همان قرارداد تقسیم می‌شود. درآمد تأییدشده کارفرما، بدون مالیات، بر همین نسبت تخصیص می‌یابد.

### سهم فرد

1. اگر روی تسک زمان واقعی ثبت شده باشد، امتیاز تسک به نسبت ثانیه‌های واقعی بین افراد تقسیم می‌شود.
2. اگر زمان ثبت نشده و فقط یک مسئول وجود داشته باشد، کل امتیاز تسک به همان فرد می‌رسد.
3. اگر چند مسئول وجود داشته باشند و زمان ثبت نشده باشد، سهم مساوی ساختگی ایجاد نمی‌شود و ردیف به‌عنوان نقص کیفیت داده اعلام می‌شود.

مبلغ نمایش‌داده‌شده فقط **سهم تحلیلی از درآمد تأییدشده** است و حقوق، پاداش، کارانه یا بدهی شرکت به فرد محسوب نمی‌شود.

گزارش امکان فیلتر و خروجی بر اساس این ابعاد را دارد:

- قرارداد
- شهر
- نوع قرارداد
- تیم
- فرد
- بازه تأیید صورت‌وضعیت

راهنمای کامل فرمول‌ها در `docs\REPORTS_FA.md` است.

## دسترسی گزارش‌ها

کنترل دسترسی در API سرور اعمال می‌شود:

- `admin`، `finance` و `reporter`: گزارش مالی سراسری.
- `manager` و `planner`: فقط تیم‌های عضو خود یا تیم انتخاب‌شده مجاز.
- `support`، `supervisor` و `employer`: بدون دسترسی به گزارش سهم مالی قراردادها.
- فقط `admin` می‌تواند وزن ارتباط نوع تسک و نوع قرارداد را تغییر دهد.
- خروجی PDF/Excel دقیقاً همان محدوده‌ای را دارد که کاربر در صفحه مجاز به مشاهده آن است.

جزئیات در `docs\ACCESS_MATRIX_FA.md` آمده است.

## اصلاح Cache و موبایل

Service Worker با نسخه `taskhub-v8-0-2-static` منتشر می‌شود و هنگام فعال‌شدن Cacheهای قدیمی را حذف می‌کند. سند اصلی و API هرگز Cache نمی‌شوند.

در صفحه ورود و خطا دکمه «پاک‌سازی نسخه ذخیره‌شده و بارگذاری مجدد» وجود دارد. این دکمه:

- Service Worker و Cache فایل‌های عمومی را حذف می‌کند.
- کلید خصوصی پیامرسان در IndexedDB را حذف نمی‌کند.
- `localStorage` را پاک نمی‌کند.

بنابراین کاربران موبایل برای رفع نسخه قدیمی نیازی به DevTools ندارند.

## پیامرسان

برای تولید کلید هیچ برنامه، افزونه یا ابزار جداگانه‌ای لازم نیست. مرورگر در اولین ورود به **پیامرسان** کلید دستگاه را خودکار می‌سازد. کلید خصوصی غیرقابل‌استخراج در IndexedDB نگهداری می‌شود و فقط کلید عمومی به سرور ارسال می‌شود.

راهنمای فعال‌سازی دستگاه دوم، کد شش‌رقمی و محدودیت بازیابی در `docs\MESSENGER_SETUP_FA.md` معتبر است.

## انتشار روی اینترنت

معماری انتخاب‌شده:

```text
Internet → HTTPS/443 روی IIS → ARR Reverse Proxy → Waitress روی 127.0.0.1:19234 → SQL Server داخلی
```

برای اینترنت از `TaskHubServer_v8_0_2.exe` استفاده شود. در این حالت:

- Certificate روی IIS نصب می‌شود.
- در کانفیگ برنامه `TASKHUB_REVERSE_PROXY=true` قرار می‌گیرد.
- فایل‌های PEM داخل کانفیگ برنامه قرار نمی‌گیرند.
- Waitress حتی در صورت باقی‌ماندن `TASKHUB_HOST=0.0.0.0` فقط روی `127.0.0.1` Bind می‌شود.
- فقط پورت 443 اینترنتی باز می‌شود؛ پورت 19234 مستقیم منتشر نمی‌شود.

دستورالعمل کامل: `docs\DEPLOY_IIS_FA.md`

