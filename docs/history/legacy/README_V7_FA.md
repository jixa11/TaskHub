# تسک هاب ۷.۱.۰

نسخه ۷ یک ارتقای افزایشی روی دیتابیس نسخه ۶.۲.۱ است. تابع و تنظیمات `connection_string()` تغییر نکرده‌اند. هنگام اولین اتصال، فقط جدول‌ها و ستون‌های جدید به‌صورت idempotent ساخته می‌شوند و داده‌های قبلی حذف یا ریست نمی‌شوند.

## مهم‌ترین تغییرها

- رفع صفحه خالی کاربران وب: داده‌های اصلی از `/api/core_data` با کنترل نقش و رکورد دریافت می‌شوند؛ UI دیگر برای بارگذاری عادی به Raw SQL API وابسته نیست.
- مدیر همه تسک‌ها را می‌بیند و ویرایش می‌کند؛ اگر خودش مسئول/همکار تسک باشد، کنترل‌های انجام کار را نیز دارد.
- نشست‌ها بر اساس کاربر گروه‌بندی می‌شوند، دستگاه‌ها جدا قابل مشاهده/بستن هستند و نشست بی‌فعالیت بعد از دو ساعت پاک می‌شود.
- نقش‌های «کارشناس مالی» و «کارشناس اجرایی» اضافه/اصلاح شده‌اند.
- قرارداد، الحاقیه، صورت‌وضعیت، برنامه مالی، پیشنهاد برنامه‌ریزی، گزارش Excel/PDF، فایل و تصویر، Audit و حذف منطقی اضافه شده است.
- مانده قرارداد فقط با مبلغ بدون مالیاتِ آخرین نسخه فعال صورت‌وضعیت که کارفرما تایید کرده کم می‌شود.
- هدف سالانه و سهم فصل/ماه با مبلغ یا درصد دستی و نسخه‌دار است. فصل ابزار تقسیم روی سه ماه و ماه منبع نهایی محاسبه است؛ کسری ماه خودکار روی ماه بعد انباشته نمی‌شود.
- تصویر تسک تا ۱۶۰۰ پیکسل به WebP تبدیل می‌شود، EXIF حذف می‌شود، thumbnail دارد و با SHA-256 deduplicate می‌شود. PDF رسمی بدون تغییر نگهداری می‌شود.
- پشتیبان ترکیبی دیتابیس+فایل با checksum و مانیفست و زنجیره FULL/DIFFERENTIAL اضافه شده است.
- هر پروژه دقیقاً یک نوع دارد: `CMS`، `CMMS`، `PM`، `نور`، `رها`، `ETL` یا `صندوق نصیر`. پروژه‌های قدیمی تا زمان تعیین نوع با برچسب «نوع تعیین نشده» مشخص می‌شوند و ذخیره پروژه بدون انتخاب نوع ممکن نیست.
- گزارش «درآمد پروژه‌ها» از نوع پروژه به پروژه و سپس قرارداد و صورت‌وضعیت باز می‌شود. مبلغ برنامه، ارسال‌شده، تاییدشده، مانده، سهم و درصد تحقق در همه سطوح به ریال نمایش داده می‌شود.
- گزارش «سهم کارکرد» فقط از زمان واقعی تایمر تسک استفاده می‌کند و سهم فرد از پروژه، تمرکز فرد روی پروژه و سهم از کل را بدون نسبت‌دادن مبلغ به افراد نشان می‌دهد.
- فیلتر زمانی داشبورد به‌طور پیش‌فرض «همه زمان‌ها» است و گزینه «هفته اخیر» و بازه دلخواه، نمودارها و فهرست‌های تاریخی را با یک بازه مشترک به‌روزرسانی می‌کند.
- گزینه‌های فرعی فرم قرارداد، الحاقیه، صورت‌وضعیت و تسک زیر «موارد بیشتر» قرار دارند و در هر بار بازشدن فرم، حتی هنگام ویرایش رکورد دارای مقدار، بسته می‌مانند.
- انتخاب‌گرهای کوتاه و محدود مانند نوع، وضعیت و اولویت فقط انتخابی‌اند و ورودی تایپی ندارند.
- کارشناس مالی شهرها و پروژه‌ها را فقط‌خواندنی می‌بیند؛ ثبت یا ویرایش آن‌ها همچنان در اختیار مدیر و پلنر است.

## اجرای امن ارتقا

1. از نسخه فعلی بکاپ SQL Server بگیرید.
2. نسخه جدید را با همان `taskhub_config.json` کنار EXE اجرا کنید. Connection String را تغییر ندهید.
3. با مدیر وارد شوید و در «تنظیمات ← سلامت سیستم» نسخه `7.1.0` را کنترل کنید.

در اولین اجرای ۷.۱، جدول انواع پروژه و ستون اجباری نوع پروژه به‌صورت افزایشی ساخته می‌شود. پروژه‌های موجود حذف یا حدس‌زده نمی‌شوند؛ مدیر یا پلنر باید از فیلتر «فقط پروژه‌های بدون نوع» آن‌ها را باز کند و نوع درست را انتخاب کند.
4. ابتدا مهاجرت را Dry Run کنید:

```bat
python migrate_legacy_v7.py --contracts "t_Contract Data.xlsx" --extensions "t_ContractExtension Data.xlsx" --statements "t_ContractStatement Data.xlsx"
```

اگر ابزارهای EXE را با `build.bat` ساخته‌اید، `TaskHubMigration_v7.exe` همین کار را بدون نیاز به Python انجام می‌دهد و سه فایل تحویلی داخل آن قرار دارند. اجرای واقعی فقط با سوییچ `--apply` انجام می‌شود.

حالت پیش‌فرض کاملاً آفلاین است: نه به SQL Server وصل می‌شود و نه جدول/داده‌ای را تغییر می‌دهد؛ فقط سه فایل Excel را می‌خواند و شمارش و قرنطینه احتمالی را گزارش می‌کند.

5. پس از تطبیق شمارش‌ها، همان دستور را با `--apply` اجرا کنید. اجرای دوباره امن است و رکوردهای دارای شناسه Legacy تکرار نمی‌شوند.

6. بعد از مهاجرت، فایل فقط‌خواندنی `sql/validate_v7_after_migration.sql` را اجرا کنید. خروجی آن شمارش‌ها، رکوردهای یتیم، مبالغ نامعتبر، تخصیص ماهانه و موارد قرنطینه را بدون تغییر هیچ داده‌ای نشان می‌دهد.

خروجی کنترل فایل‌های تحویلی فعلی در `docs/migration_dry_run.json` است: ۱۴۳ قرارداد واقعی، ۴۰ الحاقیه قابل اتصال، ۲۰۰۶ الحاقیه یتیم، ۴۷۵ صورت‌وضعیت قابل اتصال و ۵ صورت‌وضعیت یتیم. هیچ یتیم یا مبلغ مبهمی حذف نمی‌شود؛ همه به `MigrationQuarantine` می‌روند.

مبلغ ۱۷ الحاقیه متصل از منبع مشخص نمی‌کند «مبلغ تغییر» است یا «مبلغ نهایی». این موارد عمداً اثر مالی ندارند تا کارشناس مالی نوع مبلغ را تعیین و مدیر تایید کند. صورت‌وضعیت‌های قدیمی نیز خودکار «تایید کارفرما» فرض نمی‌شوند.

## بکاپ و بازیابی

- بکاپ دستی از تنظیمات قابل ساخت و دانلود است.
- اجرای زمان‌بندی‌شده: `backup.bat`؛ برای FULL اجباری: `python backup.py --full`.
- خروجی ساخت ویندوز همچنین `TaskHubBackup_v7.exe` و `TaskHubRestore_v7.exe` می‌دهد تا سرور برای این دو عملیات به نصب Python وابسته نباشد.
- هر فایل `.taskhubbackup` شامل بکاپ SQL، فایل‌های لازم، مانیفست و SHA-256 است. Connection String و رمز دیتابیس داخل آرشیو نیست.
- اگر SQL Server روی دستگاه دیگری است، متغیر `TASKHUB_SQL_BACKUP_DIR` را روی یک مسیر UNC مشترک تنظیم کنید که هم سرویس SQL Server و هم برنامه اجازه خواندن/نوشتن آن را داشته باشند. برای بازیابی می‌توان `TASKHUB_SQL_RESTORE_DIR` را جدا تعیین کرد. این تنظیم‌ها فقط مسیر فایل بکاپ‌اند و Connection String را تغییر نمی‌دهند.
- بازیابی یک فایل خاص:

```bat
python restore_backup.py checkpoint.taskhubbackup --attachment-sha HASH
```

- بازیابی کامل باید با برنامه متوقف‌شده انجام شود و قبل از شروع، نقطه نجات FULL جدید می‌سازد:

```bat
python restore_backup.py checkpoint.taskhubbackup --confirm RESTORE-TASKHUB-v7
```

## اصلاح View سامانه Cms

فایل `sql/fix_v_InspectionMaterialAnalysisStrings.sql` جداگانه و دستی روی دیتابیس `Cms` اجرا می‌شود. ضریب دستمزد در دو خروجی یکسان شده و join چندردیفی نوع طراحی حذف شده است. این اسکریپت به Connection String تسک هاب دست نمی‌زند.

## داده‌های تکمیلی قدیمی

در خروجی‌های فعلی، فایل داده چهار جدول `t_ContractStatementFactorList`، `t_ContractStatementTax`، `t_ContractStatementTaxInfo` و `t_ContractStatemenLog` وجود ندارد. ساختار مقصد برای ردیف‌ها/رویدادهای مالیاتی آماده است، ولی تبدیل محتوای آن‌ها فقط پس از دریافت خروجی واقعی انجام می‌شود. فیلدهای مالیاتی موجود در فایل اصلی صورت‌وضعیت همین حالا منتقل می‌شوند.

## ساخت EXE

`build.bat` چهار خروجی در پوشه `dist` می‌سازد: برنامه اصلی، مهاجرت، بکاپ و بازیابی. اجرای سروری برنامه اصلی:

```bat
TaskHub_v7.exe --server
```

اسکریپت ساخت از محیط مجازی محلی `.venv-build` استفاده می‌کند و تنظیمات سراسری `pip` یا ویندوز را تغییر نمی‌دهد.
قبل از ساخت EXE، تست‌های واحد و تست دودِ API/PDF/Excel به‌صورت خودکار اجرا می‌شوند و در صورت شکست، ساخت متوقف می‌شود.

پیش‌نیاز ساخت، Python 64-bit نسخه 3.11 یا 3.12 است. هنگام نصب Python گزینه `Add python.exe to PATH` را فعال کنید. اسکریپت ابتدا `py -3` و سپس `python` را امتحان می‌کند؛ بعد از نصب یا اصلاح PATH باید پنجره Command Prompt قبلی را ببندید و دوباره باز کنید.
