# گزارش آزمون TaskHub 8.0.2

تاریخ بازبینی سورس: 2026-07-25

## آزمون‌های خودکار

در بازبینی نهایی سورس، دستور `python run_tests.py` اجرا شد:

```text
Ran 72 tests
OK (skipped=2)
```

دو مورد Skip فقط مقایسه خودکار با سورس ۶.۲.۱ هستند، چون آن سورس مرجع داخل بسته نسخه ۸.۰.۲ قرار ندارد. پوشش اضافه‌شده نسخه ۸.۰.۲ شامل موارد زیر است:

- فرمول امتیاز تسک از وزن پیشرفت و وزن نوع تسک/نوع قرارداد.
- اولویت زمان واقعی در سهم فرد.
- عدم تقسیم مساوی ساختگی برای چند مسئول بدون زمان.
- تخصیص نسبی درآمد تأییدشده و برچسب تحلیلی بودن مبلغ.
- Migration یک‌باره قراردادهای موجود به `نوع تعیین نشده`.
- فعال‌بودن فروش، توسعه، پشتیبانی و نوع تعیین نشده.
- توسعه همان گزارش درآمد موجود با شهر و نوع قرارداد، بدون صفحه تکراری.
- خروجی PDF و Excel گزارش‌های مالی و تیمی.
- کنترل دسترسی سمت سرور و Scope تیم برای مدیر/پلنر؛ کاربر تیمی بدون عضویت فعال هیچ داده مالی سراسری دریافت نمی‌کند.
- اعتبارسنجی تعلق قرارداد تسک به پروژه تسک و محدودکردن فهرست قرارداد فرم به همان پروژه.
- نسخه‌گذاری Service Worker، حذف Cache قدیمی و حفظ IndexedDB پیامرسان.
- بسته‌بندی Waitress، IIS/ARR و Bind اجباری Reverse Proxy روی `127.0.0.1`.
- کنترل تعداد Markerهای SQL در دستورات Literal نسخه ۸ و ۸.۰.۲.
- کنترل نحوی Python و JavaScript.

## آزمون‌های Smoke

در محیط فعلی Linux، اجرای Smoke به‌دلیل نصب‌نبودن وابستگی `Flask` ممکن نبود و با `ModuleNotFoundError` متوقف شد. نصب اینترنتی پکیج‌ها نیز در این محیط در دسترس نبود. این محدودیت به‌صراحت ثبت شده و به‌عنوان موفقیت گزارش نشده است.

`build.bat` روی Windows ابتدا `requirements.txt` را در محیط مجزای `.venv-build` نصب می‌کند و سپس، پیش از ساخت فایل اجرایی، این دو Smoke را اجرا می‌کند:

```text
tests\smoke_flask_v7.py
tests\smoke_flask_v8.py
```

Smokeها بدون اتصال به دیتابیس واقعی، Routeها، احراز هویت، تعداد پارامترهای SQL، Export و مسیرهای اصلی API را با Connection ساختگی کنترل می‌کنند.

## آزمون‌هایی که در این محیط اجرا نشدند

- اتصال و Migration روی SQL Server واقعی سازمان.
- Build نهایی PyInstaller روی Windows.
- نصب و پیکربندی واقعی IIS، ARR، DNS و Certificate عمومی.
- تست عملی Chrome/Edge/Android/iPhone و WebView2.
- Load Test هم‌زمان کاربران اینترنتی.
- بازیابی واقعی Backup روی SQL Server آزمایشی.

## تست‌های الزامی قبل از Production

1. Full Backup از دیتابیس و `taskhub_data`.
2. اجرای اولین‌بار روی کپی دیتابیس و کنترل `taskhub_log.txt`.
3. اجرای `sql\validate_v802.sql` و کنترل اینکه همه قراردادهای قبلی فقط یک‌بار روی «نوع تعیین نشده» قرار گرفته‌اند.
4. ثبت یک قرارداد برای هر نوع و کنترل گزارش شهر/نوع قرارداد.
5. ثبت تسک‌های تکمیل‌شده با قرارداد، تیم، یک مسئول، چند مسئول و Timer واقعی.
6. تطبیق دستی یک نمونه محاسبه سهم تیم و فرد با فرمول مستند.
7. تست PDF و Excel برای admin، finance، reporter، manager و planner.
8. اطمینان از رد دسترسی support به سهم مالی.
9. تست Cache Update روی موبایلی که نسخه ۸.۰.۱ را قبلاً باز کرده است.
10. اجرای `TaskHubServer_v8_0_2.exe` پشت IIS و کنترل اینکه TCP/19234 از اینترنت قابل دسترسی نیست.
11. کنترل `https://domain/api/ping` و ورود، پیامرسان، دانلود PDF و آپلود فایل از اینترنت.
